# Space of us V3 项目课堂展示答辩文档

## 1. 项目概述

`Space of us V3` 是一个面向情侣场景的私密共享空间系统，核心目标是把“共同回忆、地点足迹、约定事项、纪念日、收藏清单、时光胶囊”等内容整合到同一个数字产品中，形成兼具情感表达与轻量协作能力的个人化应用。

与普通社交平台不同，这个项目强调的是“小范围、强私密、强陪伴”的产品定位。用户不是面向陌生人发布内容，而是围绕固定的情侣关系进行双人数据共享。因此，项目在设计上重点关注了以下几个方向：

- 私密空间感：整体界面强调情绪化表达和陪伴氛围。
- 双人协作：支持情侣绑定、共同维护内容、共享数据。
- 多端访问：既可以作为 Web 网站运行，也可以封装为桌面端应用。
- 数据可迁移：支持从本地文件存储逐步迁移到云端 Supabase。

## 2. 项目要解决的问题

现实中的情侣共同生活信息往往分散在微信、备忘录、相册、地图收藏、日历提醒等多个应用中，存在以下问题：

- 内容分散，不利于统一管理。
- 纪念内容容易遗失，缺少沉浸式展示。
- 双方共享和同步不方便。
- 缺少一个兼具情感价值和实用价值的专属空间。

因此，本项目希望构建一个“情侣专属数字空间”，把地图、回忆、约定、点单、纪念日等内容统一沉淀到一个系统中。

## 3. 核心功能模块

### 3.1 入口与认证模块

系统首页是一个沉浸式登录入口，支持：

- 普通用户登录
- 新用户注册
- 邮箱验证码注册
- 密码找回
- 管理员登录

项目采用基于 Cookie 的会话认证，并区分普通站点身份与管理员身份。管理员登录后可进入后台，查看注册用户、绑定状态、系统告警，并对用户密码进行重置。

### 3.2 地图主页模块

地图主页是项目的核心展示入口之一。系统基于中国地图实现可交互的“足迹地图”，用户可以：

- 查看中国地图
- 高亮已经点亮的省份
- 点击进入某个省份页面
- 结合照片与回忆展示旅行轨迹

这一部分不是简单的静态地图展示，而是把“情感足迹”可视化，增强了产品的展示效果和答辩时的视觉冲击力。

### 3.3 回忆与记忆管理模块

系统提供回忆记录、最近回忆、记忆归档等能力，用于保存情侣之间的重要内容。它既能承载纯文字，也能和图片、地点、时间等信息结合，形成结构化回忆。

### 3.4 情侣绑定模块

这是项目区别于普通个人应用的重要部分。系统支持：

- 生成邀请码
- 发起绑定请求
- 对请求进行接受或拒绝
- 绑定后形成双人共享作用域

绑定成功后，双方的数据不再只是“个人数据”，而是进入“情侣共享空间”，后续的收藏、约定、纪念日等都可以按情侣范围同步。

### 3.5 情侣中心模块

情侣中心是 V3 的特色模块，集成了多种轻社交与生活协作能力，例如：

- 情侣约定管理
- 情侣专属菜单
- 奶茶/餐品偏好记录
- 双方代下单提醒
- 订单状态更新

这一模块体现了项目不仅仅是“相册”或“纪念册”，而是向“情侣生活协作平台”方向延伸。

### 3.6 收藏与纪念日模块

项目支持保存共同收藏内容，并管理纪念日信息。纪念日可以用于展示重要节点，收藏则可以沉淀共同喜欢的地点、物品或计划。

### 3.7 时光胶囊模块

时光胶囊模块用于保存面向未来开启的内容，增强了产品的仪式感和情感延迟体验，是典型的情感化产品设计。

### 3.8 设置与后台管理模块

系统还包含设置页与后台管理能力，支持：

- 系统参数读取
- 登录页展示内容配置
- 管理员查看用户信息
- 管理员查看告警
- 管理员重置用户密码

## 4. 技术架构设计

### 4.1 总体架构

本项目采用的是“前后端一体化 Web 架构 + 桌面端封装”的方案。

整体可以概括为四层：

1. 表现层：基于 Next.js App Router 构建页面与交互界面。
2. 业务层：通过 Next.js Route Handler 提供认证、共享数据、账户、情侣绑定等接口。
3. 数据层：使用本地 JSON 文件和 Supabase 两套存储方案。
4. 客户端封装层：通过 Electron 将 Web 项目封装成桌面应用。

### 4.2 前端架构

前端主要基于以下技术：

- `Next.js 16`
- `React 19`
- `TypeScript`
- `Tailwind CSS 4`
- `Framer Motion`
- `Lucide React`
- `d3-geo`

前端采用 Next.js 的 `App Router` 目录式路由，页面划分清晰，例如：

- `app/page.tsx`：系统首页
- `app/map/page.tsx`：地图主页
- `app/couple/page.tsx`：情侣中心
- `app/memories/page.tsx`：回忆页
- `app/anniversaries/page.tsx`：纪念日页
- `app/settings/page.tsx`：设置页

组件层采用拆分式设计，例如：

- `EntryExperience.tsx`：登录注册与后台入口
- `ChinaMap.tsx`：中国地图渲染与交互
- `CoupleHub.tsx`：情侣中心复合业务组件
- `MemoryArchive.tsx`、`RecentMemories.tsx`：回忆相关组件

这种结构的优点是页面职责清楚、组件复用度高，后续便于迭代。

### 4.3 后端架构

本项目没有单独拆出独立后端服务，而是直接利用 Next.js 的服务端能力，在 `app/api` 下实现接口。这种方式适合中小型项目开发，能降低前后端联调成本。

目前主要接口包括：

- `/api/auth/login`：登录与退出
- `/api/auth/email-code`：邮箱验证码
- `/api/auth/password-recovery`：密码找回
- `/api/accounts`：账户注册、密码重置
- `/api/account-binding`：情侣绑定
- `/api/couple`：情侣中心数据交互
- `/api/shared-items`：共享收藏/纪念内容
- `/api/memories`：回忆数据
- `/api/app-settings`：应用配置

后端运行时主要使用 `Node.js runtime`，适合处理文件操作、鉴权、Supabase 管理端请求等逻辑。

### 4.4 数据存储架构

项目的数据层是一个比较有代表性的亮点：它兼容“本地存储模式”和“云端持久化模式”。

#### 本地存储

在桌面端或本地开发环境中，系统可以将数据保存在 JSON 文件中，例如：

- `data/accounts.json`
- `data/couple-hub.json`
- `data/localMemories.json`

优点是部署简单、便于快速开发和调试。

#### 云端存储

在线上环境中，项目通过 `Supabase` 进行数据持久化，主要承担：

- 账户与共享数据存储
- 上传图片对象存储
- 多设备数据同步

项目中的 `lib/server/supabase.ts` 对云端读写进行了统一封装，包括：

- JSON 数据读写
- 图片上传
- 私有图片签名访问
- 存储配额异常处理
- 管理员告警记录

这一设计使得系统具备从“本地原型”向“真实在线产品”过渡的能力。

### 4.5 鉴权与安全设计

项目在 `lib/server/auth.ts` 中实现了基础鉴权机制，主要特点包括：

- 使用 HMAC 对 Cookie 载荷签名
- 区分普通用户会话与管理员会话
- 会话设置过期时间
- 使用 `httpOnly Cookie` 降低前端脚本窃取风险

在账户层，密码并不是明文保存，而是通过基于密钥的哈希方式进行处理。虽然这不是完整的企业级身份系统，但对于课程项目而言，已经体现了安全意识和分层设计思路。

### 4.6 双人作用域设计

本项目有一个很有答辩价值的技术点，就是“情侣共享作用域”。

系统在账户存储中通过用户 ID 和伴侣 ID 计算作用域：

- 未绑定时，数据属于个人作用域
- 绑定后，数据进入情侣共同作用域

这样做的意义是：

- 避免不同情侣之间数据混淆
- 支持“单人使用”平滑升级为“双人共享”
- 方便后续扩展为更多共享模块

这是一种比较典型的业务建模思路，说明系统不是简单做页面，而是考虑了数据边界和业务抽象。

### 4.7 地图可视化设计

地图模块使用了 `d3-geo` 进行地理投影与路径计算，并结合 SVG 实现交互式中国地图。

地图层的主要能力包括：

- GeoJSON 数据解析
- 中国地图轮廓绘制
- 省份高亮
- 鼠标悬停提示
- 点击进入省份详情页
- 南海诸岛独立 inset 显示

这部分体现了前端可视化能力，也显著提升了项目的展示效果。

### 4.8 桌面端封装架构

项目通过 `Electron` 将 Next.js 应用封装为桌面端，主要逻辑在 `electron/main.js` 中实现。

桌面端方案的流程大致如下：

1. Electron 启动应用。
2. 自动寻找可用端口。
3. 启动本地 Next.js 服务。
4. 打开桌面窗口加载对应地址。
5. 使用本地数据目录保存用户数据和鉴权配置。

这样做的优势是：

- Web 版本与桌面版本共用大部分代码
- 便于离线或本地部署演示
- 更适合做课程成果展示和交付

## 5. 典型业务流程

### 5.1 用户注册登录流程

1. 用户进入首页。
2. 选择注册，填写用户名、邮箱、密码。
3. 系统发送邮箱验证码。
4. 验证成功后完成注册。
5. 登录成功后写入会话 Cookie。
6. 页面跳转到地图主页。

### 5.2 情侣绑定流程

1. 用户 A 生成邀请码。
2. 用户 B 输入邀请码发起绑定。
3. 系统创建绑定请求。
4. 请求被确认后，双方互相记录 partner 信息。
5. 共享数据作用域从单人切换为双人。

### 5.3 共享数据流程

1. 前端页面通过 `fetch` 请求对应 API。
2. 后端先校验会话身份。
3. 根据当前用户计算作用域 key。
4. 读取 Supabase 或本地存储中的对应数据。
5. 返回给前端渲染。

这个流程说明项目已经具备了较完整的数据闭环。

## 7. 当前不足与后续优化方向

虽然项目完成度较高，但仍有一些可以继续优化的方向：

- 安全性还可以进一步增强，例如采用更标准的密码哈希方案与更完善的权限控制。
- 数据库结构可以从当前的 JSON Key-Value 方式进一步规范化。
- 接口层可以补充更系统的参数校验与异常监控。
- 可以增加移动端适配和消息提醒能力。
- 可以增加自动化测试，提高系统稳定性。

如果从课程答辩角度回答，这部分可以体现“我对系统问题有反思，也有后续规划”。

## 8. 总结

`Space of us V3` 是一个面向情侣场景的综合型私密空间项目。它以 `Next.js + React + TypeScript` 为核心技术栈，结合 `Supabase` 完成数据持久化，并通过 `Electron` 实现桌面端封装。

从产品层面，它解决了情侣共同回忆、约定事项、收藏内容和共享生活信息分散的问题；从技术层面，它体现了前后端一体化开发、地图可视化、双人共享作用域建模、多存储方案兼容和桌面端封装等能力。

因此，这个项目不仅具有一定的实用价值，也具备较好的课程展示和答辩表达价值。

## 9. 答辩时可以直接使用的简短介绍

大家好，我展示的项目叫 `Space of us V3`。这是一个面向情侣场景的私密共享空间系统，主要用于记录两个人的共同回忆、旅行足迹、纪念日、收藏内容以及日常约定。项目采用 `Next.js` 和 `React` 进行前端开发，后端接口基于 Next.js 自带的 Route Handler 实现，数据层同时支持本地 JSON 存储和 Supabase 云端持久化，并通过 Electron 封装成桌面端应用。这个项目的特色在于，它不仅完成了页面展示，还设计了情侣绑定、共享数据作用域、地图可视化和多端运行方案，因此在产品思路和技术实现上都比较完整。

## 10. 答辩时老师可能会问的问题

### 10.1 为什么选用 Next.js？

因为 Next.js 支持前后端一体化开发，既能写页面，也能直接写服务端接口，适合课程项目快速搭建完整系统，降低了前后端联调成本。

### 10.2 为什么要同时支持本地存储和 Supabase？

因为本地存储便于开发和桌面端离线演示，而 Supabase 适合线上部署和多设备同步，两者兼容让系统更容易从原型演进到实际可用产品。

### 10.3 这个项目最大的技术亮点是什么？

我认为有三个亮点：第一是情侣共享作用域的设计；第二是中国地图的可视化交互；第三是 Web 与 Electron 桌面端共用一套业务代码。

### 10.4 未来还会怎么优化？

未来可以继续优化数据库结构、安全机制、自动化测试、移动端适配以及通知提醒功能，让它从课程项目进一步走向可长期使用的产品。
