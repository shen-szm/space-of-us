# 游客只读主页与登录路由分离设计

## 目标

将公开访问与真实情侣空间彻底分离：

- 未登录用户访问 `/` 时进入独立的游客演示地图。
- 原登录、注册、找回和管理员登录界面迁移到 `/login`。
- 登录成功后进入 `/map`，已登录用户访问 `/` 时也跳转 `/map`。
- 游客只能浏览主页演示地图，不能访问真实数据、其他功能页或任何写操作。

## 路由与访问规则

### `/`

- 未登录：显示游客演示主页。
- 已登录站点用户或管理员：服务端重定向到 `/map`。
- 页面使用独立演示数据，不请求真实用户的回忆、照片、情侣关系、订单、收藏或设置。
- 页面保留地图浏览、缩放和省份查看等纯展示交互。
- 页面显示清晰但克制的“游客预览”状态，以及前往 `/login` 的登录入口。
- 不显示情侣中心、设置、反馈、编辑、上传、收藏、绑定或管理员入口。

### `/login`

- 承载当前 `EntryExperience`。
- 保留登录、注册、找回密码和管理员登录能力。
- 普通用户登录成功后跳转 `/map`。
- 管理员登录后维持现有管理员跳转规则。

### 认证页面

以下页面必须要求真实登录会话：

- `/map`
- `/couple`
- `/memories`
- `/favorites`
- `/anniversaries`
- `/time-capsule`
- `/settings`
- `/feedback`
- `/province/[id]`
- `/admin/inbox` 继续要求管理员会话

未登录访问普通认证页面时跳转 `/login`；管理员页面继续显示或返回管理员未授权状态，不降级为游客访问。

## 权限模型

游客不是账户，也不签发游客 Cookie。

- 游客页面只读取打包在代码中的演示数据。
- 真实数据 API 保持认证要求。
- 所有写接口继续在服务端校验真实会话。
- 游客直接调用写接口时返回 `401 Authentication required`。
- 前端隐藏写控件只是体验层处理，后端认证才是权限边界。

## 演示数据

游客主页使用固定、无隐私的示例数据：

- 示例点亮省份和进度。
- 示例城市或公开占位说明。
- 不使用 Supabase 用户数据、服务器 JSON 账户数据或本地登录用户缓存。
- 不展示真实回忆照片、昵称、纪念日、天气偏好或情侣关系。

演示数据应收口在独立模块中，避免与真实地图数据源混用。

## 界面设计

沿用现有温柔、克制的地图视觉，不新增营销落地页结构。

- 顶部品牌区增加低强调度“游客预览”标识。
- 登录入口使用明确的“登录进入自己的空间”文案。
- 地图区域保持主视觉地位。
- 只读状态通过文案和缺少编辑控件表达，不使用大面积警告条。
- 移动端保持地图可浏览，登录入口始终可到达。
- 所有交互保留键盘焦点态和 WCAG AA 对比度。

## 会话与跳转

1. 未登录访问 `/`，服务端渲染游客主页。
2. 点击登录进入 `/login`。
3. 登录成功，服务端设置现有认证 Cookie，客户端跳转 `/map`。
4. 已登录用户再次访问 `/`，服务端直接重定向 `/map`。
5. 用户退出登录后清除认证 Cookie，并返回 `/`。
6. 未登录直接访问认证页面时跳转 `/login`，可附带安全的 `next` 参数以便登录后返回原目标。

`next` 只允许站内绝对路径，禁止协议、域名和双斜杠开头的值，避免开放重定向。

## 错误与边界状态

- 无法读取会话时按未登录处理，展示游客主页。
- 游客演示数据始终有本地默认值，不依赖网络接口。
- 登录页接口错误沿用现有表单反馈。
- 写接口未授权统一返回 401；管理员接口未授权保持 403。
- 页面不因 Supabase、Resend 或用户数据服务不可用而阻塞游客主页。

## 测试要求

- 路由测试：`/` 的登录与未登录分支正确。
- 登录路由测试：`/login` 渲染现有登录体验。
- 认证保护测试：未登录访问每个私有页面都会进入 `/login`。
- 开放重定向测试：非法 `next` 参数被忽略。
- API 测试：无会话调用所有写接口均被拒绝。
- 数据隔离测试：游客主页源码不导入真实账户、回忆、情侣或设置存储。
- 浏览器回归：桌面和手机检查游客标识、地图浏览和登录入口。
- 完整执行 `npm test`、`npm run lint`、`npm run build`。

## 非目标

- 不创建可持久化的游客账户。
- 不允许游客提交反馈、收藏、订单或回忆。
- 不开放情侣中心等其他页面的游客预览。
- 不修改真实用户数据结构。
- 不新增社交登录或新的 onboarding。
